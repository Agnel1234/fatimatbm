OVERVIEW
================================================================================

V4 introduces pagination and advanced filtering support for the Fatima Church
Forms application. The main changes are NEW stored procedures and indexes to
support efficient querying of large subscription datasets.

NO BREAKING CHANGES: All V3 tables and schemas remain intact. V4 is purely
additive (new indexes and procedures).

WHAT'S NEW IN V4 (TO BE DEPLOYED)
================================================================================

NEW INDEXES (for performance optimization):
  - IX_family_subscription_yearly_year
  - IX_family_subscription_yearly_family
  - IX_family_subscription_yearly_status  (with INCLUDE columns)
  - IX_family_subscription_yearly_composite
  - IX_cemetery_subscription_yearly_family
  - IX_cemetery_subscription_yearly_status  (with INCLUDE columns)
  - IX_cemetery_subscription_yearly_composite

NEW STORED PROCEDURES:

  1. sp_GetAllSubscriptions
     - Gets all family and cemetery subscriptions with pagination
     - Parameters: @pageNumber (default 1), @pageSize (default 50)
     - Returns: Combined family + cemetery subscription rows
     - Purpose: Power the new Subscription tab grid

  2. sp_GetSubscriptionsFiltered
     - Gets filtered subscriptions with pagination
     - Parameters: @pageNumber, @pageSize, @familyName, @anbiyamId,
                  @subscriptionType (Family/Cemetery), @status (Paid/Pending),
                  @yearFrom, @yearTo
     - Returns: Filtered subscription rows
     - Purpose: Support advanced filtering in Subscription tab

  3. sp_GetSubscriptionTotalCount
     - Gets total count of matching subscriptions (for pagination UI)
     - Same parameters as sp_GetSubscriptionsFiltered
     - Returns: Single row with TotalCount column
     - Purpose: Calculate total pages in client UI

  4. sp_SetCemeterySubscription
     - Upserts cemetery subscription (insert or update by family_id + year)
     - Parameters: @family_id, @subscription_year, @amount, @payment_date,
                  @payment_status
     - Returns: None (success/error via exception)
     - Purpose: Persist cemetery subscription changes from CemeterySubscriptionPopup

DEPLOYMENT INSTRUCTIONS
================================================================================

STEP 1: Backup Production Database
  - Take a backup snapshot of fatimachurchtbm database before deploying
  - Document the timestamp for rollback purposes if needed

STEP 2: Run V4 Scripts
  Execute in this order on the Production RDS instance:

  a) V4_ddl_Scripts.sql
     - Creates new indexes on existing tables
     - Idempotent: uses IF NOT EXISTS checks
     - Estimated runtime: < 1 minute

  b) V4_dml_Scripts.sql
     - Creates 4 new stored procedures
     - Idempotent: uses CREATE OR ALTER
     - Estimated runtime: < 30 seconds

STEP 3: Validate Deployment
  Run validation queries:

  -- Check indexes were created
  SELECT name, object_name, type_desc
  FROM sys.indexes
  WHERE object_id IN (OBJECT_ID('dbo.family_subscription_yearly'),
                      OBJECT_ID('dbo.cemetery_subscription_yearly'))
  AND name LIKE 'IX_%'
  ORDER BY object_name;

  -- Check stored procedures were created
  SELECT name, type_desc
  FROM sys.objects
  WHERE name IN ('sp_GetAllSubscriptions', 'sp_GetSubscriptionsFiltered',
                 'sp_GetSubscriptionTotalCount', 'sp_SetCemeterySubscription')
  ORDER BY name;

  -- Test sp_GetAllSubscriptions
  EXEC dbo.sp_GetAllSubscriptions @pageNumber = 1, @pageSize = 10;

  -- Test sp_GetSubscriptionTotalCount
  EXEC dbo.sp_GetSubscriptionTotalCount;

STEP 4: Deploy Application Code
  - Build and deploy the updated Windows Forms application
  - Application will use new Subscription tab and procedures

================================================================================
ROLLBACK PROCEDURE
================================================================================

If V4 deployment causes issues:

1. Restore database from backup (Step 1)
2. Revert application code to previous version
3. Verify application functionality

Quick rollback (without restoring entire database):
  -- Drop new indexes
  DROP INDEX IF EXISTS dbo.IX_family_subscription_yearly_year
    ON dbo.family_subscription_yearly;
  DROP INDEX IF EXISTS dbo.IX_family_subscription_yearly_family
    ON dbo.family_subscription_yearly;
  -- ... (repeat for other new indexes)

  -- Drop new stored procedures
  DROP PROCEDURE IF EXISTS dbo.sp_GetAllSubscriptions;
  DROP PROCEDURE IF EXISTS dbo.sp_GetSubscriptionsFiltered;
  DROP PROCEDURE IF EXISTS dbo.sp_GetSubscriptionTotalCount;
  DROP PROCEDURE IF EXISTS dbo.sp_SetCemeterySubscription;

Note: Dropping indexes will not break existing functionality but may impact
performance of the new Subscription tab.
